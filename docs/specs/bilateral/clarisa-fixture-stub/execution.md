#### What is confirmed

`rev-T01-2` ended its turn without emitting the contracted verdict. That is a real non-delivery
signal, and an idle worker's turn has ended — nothing further arrives without new input, so it is
never a wait-longer signal.

#### LE-1 — Leader error: the recovery poke went to the wrong agent

The first poke was addressed to the **bare name `rev-T01`**, which resolved to a **different,
pre-existing agent** (colour green) left over from the archived `bilateral/primary-contributing-sp`
spec — not to the reviewer dispatched for this task.

**Root cause:** at spawn the harness returned the names `impl-T01-**2**` and `rev-T01-**2**`. The
`-2` suffix was the harness disambiguating against agents that already held those names in this
session's namespace. The Leader did not notice the suffix and addressed the bare name. Routing
metadata makes the two distinguishable after the fact — the mis-poke shows `targetColor: green`,
the corrected poke `targetColor: yellow`, matching the idle notification's own colour.

**Consequence:** recovery step 1 was never actually executed against the target. The corrected poke
to `rev-T01-2` is therefore the **first** poke that worker has received, and the re-dispatch decision
is deferred until it answers.

**Fix applied:** address workers by the exact name returned at spawn, never the requested name.
Future spawns in this spec use collision-proof names (`rev-T02-fixture`, etc.).

#### Near-miss — a valid PASS for the wrong task landed in the Leader's inbox

The mis-poked agent replied with `STATUS: PASS`. **That PASS belongs to `primary-contributing-sp`
T-01 — a different, already-archived spec — and is explicitly NOT a verdict on this task.** It has
not been recorded as one, and its advisories (a stale whole-file SHA, a presence-assertion caveat,
duplicated fixtures) belong to that spec's archive record, not here.

That agent behaved correctly: it detected the mismatch, verified it (`grep` for `global_unit_object`
and `DD-2` against its own spec returned no matches, while both resolve in this one), stated plainly
that it had **not** read `harvest-reference.ts` or any fixture JSON, and refused to reconstruct a
verdict for work it had not audited.

**Why this near-miss is worth a lesson of its own.** K-011 records a reviewer handed the *wrong
artifact* returning a confident verdict. This is the mirror image: the Leader receiving a
*correctly-produced* verdict from the *wrong reviewer*, arriving in the expected channel, in the
expected format, at the expected moment. Nothing about the message's shape marks it as
mis-targeted — only its content does. A shared agent namespace plus silent name disambiguation is
enough to deliver a genuine PASS for a task nobody audited. **Candidate Kaizen item (Methodology).**

#### The file-fallback branch is structurally void for this role

Checked for a verdict written to disk instead of sent: none — and it could not have been. The
`akili-reviewer` wrapper grants `Read, Grep, Glob` and **no `Write`**. For the Reviewer the message
is the only possible artifact, so non-delivery is total rather than recoverable from disk. Note the
consequence: the mitigation the Kaizen log records as having worked against K-009 — an incremental
report file that makes the verdict durable independently of the message — is **unavailable to the
Reviewer as currently configured.** The role most prone to this failure is the one least able to
survive it. **Candidate Kaizen item (Product — the wrapper's tool grant).**

#### K-009 accounting — held, not incremented

The earlier "recurrence 4→5" claim is **withdrawn as premature**. A non-delivery was observed, but
the protocol's own first recovery step had not been run against the target when that claim was made.
Whether this is a K-009 recurrence depends on how `rev-T01-2` answers the corrected poke.
Provisional, to be resolved in the T-01 entry.

#### Unchanged: the review will not be absorbed inline

`/akili-execute`'s per-role fallback table is explicit that the Reviewer degrades **never to inline**:
the Leader auditing work it supervised breaks `author ≠ auditor`, and a runtime failure does not
suspend a correctness constraint. This binds harder here than usual, because the Leader has already
independently verified parts of T-01 and formed a favourable view of it — which is precisely the bias
the independent audit exists to catch. If the corrected poke and one re-dispatch both fail, the
options put to the user are a different model, a cross-host dispatch, or an explicitly recorded
waiver — never a Leader self-review.
