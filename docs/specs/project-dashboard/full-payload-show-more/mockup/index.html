          What this mockup settles

          QuestionAnswer it gives
          OQ-3 — bounded height: fixed or viewport-relative? Viewport-relative, max-height:46vh — taller than the collapsed card on a laptop while still fitting beside the right column. A fixed pixel bound either wastes a tall screen or overflows a short one. But the bound alone is not the answer — see DD-13 below.
          DC-8 — which sibling does an unbounded expansion actually stretch? Both, and the second one is the trap. Flip to 1 · Unbounded and expand Results Partners: its row-mate in the nested 2-column grid stretches, and the whole right-hand column (Results by indicator / by status) stretches through the outer items-stretch. Revision 2 named the wrong adjacency; the human-check script now names both.
          DD-13 — is bounding the list enough? No. This is what the mockup caught that reading the code did not. Compare 2 · Bounded + stretch against 3 · Independent. Bounding stops the page growing, but lg:items-stretch still forces the row-mate to match the expanded card, so Primary Levers grows a tall empty gap with its 5 rows stranded at the top and its “Show more” pushed far below the content. Padding that gap with rows nobody asked for would break the ticket’s scope — so the fix is the height, not the content: while any card in the row is expanded the grid switches to align-items:start. Collapsed it keeps items-stretch, so the default view does not change.
          DD-4 — the colour consequence Collapsed, row 5 is #345b8f (middle), not navy. Expanded, row 137 is the one painted #112F5C. Encoding is computed over the full list, so nothing already on screen changes when you expand — that is R-PDB-004, and you can verify it by eye here.
          R-PDB-002 AC.2 — no toggle when ≤ 5 Contributing projects has 15 rows and Primary Levers 6, so both show a toggle; a section of ≤ 5 renders none. canExpand() lives in the card beside the toggle.
          NFR-PDB-003 — a11y Each toggle is a real <button> with aria-expanded and an accessible name carrying its chart title, so four “Show more” buttons are distinguishable. Tab to them and press Enter/Space.
          Render cost at the measured worst case 137 rows in one card, from GATE-1. Comfortable — the concern this mockup was going to test (“hundreds of rows”) is not what the data contains.

          Fidelity limits, stated so this is not over-read: system fonts stand in for Barlow / Space Grotesk (no external resources), and the geographic card is a placeholder because Chunk A does not touch it. Everything else — grid columns, gaps, bar geometry, rank chips, colour ramp, toggle placement inside the items arm — mirrors the real templates.
