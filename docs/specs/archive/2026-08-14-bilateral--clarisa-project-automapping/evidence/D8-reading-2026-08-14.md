## 2. Test — the coverage number (answers OQ-1)

Against `https://clarisatest-back.ciat.cgiar.org/`:

| Tier | Contracts | % of 1543 |
| --- | --- | --- |
| `EXACT_CODE` | 32 | 2.07 % |

| `AMBIGUOUS` | 0 | 0 % |
| `UNRESOLVED` | 1207 | 78.22 % |

### How to read the 78 % — it does not mean what it looks like

The denominator is **1543 AGRESSO bilateral contracts**, but only **380 CLARISA Alliance-2026 projects** exist to match against. The theoretical ceiling is therefore `380 / 1543 = 24.6 %`.

| Metric | Value |
| --- | --- |
| Resolved | **336** contracts |
| As % of contracts | 21.8 % |
| **As % of the reachable ceiling** | **88.4 %** |

The 1207 unresolved contracts overwhelmingly have **no corresponding Alliance-2026 project at all** — they are other phases, other centres, older agreements. They are not matcher failures. Quoting "78 % unresolved" without the ceiling would misrepresent the instrument's performance by a factor of four.

## 3. Four findings that change S2's design

**① The prefix rule is the workhorse — 9.5× the exact match.**
304 normalized vs 32 exact. The proposal's §4.3 inference is now measured fact: `external_code` mismatch is a systematic centre prefix, and **DD-4's closed-set strip is what actually produces coverage**. Exact matching alone would have delivered 2 %.

**② `FULL_NAME` resolved ZERO.**
The proposal positioned name comparison as "a fallback for the residue". It contributed **nothing** on real data. For S2 it is dead weight as implemented, and this is only knowable by measuring — the design could not have predicted it.

**③ Zero collisions on live data.**
OQ-3 was closed in August on a static probe; the injectivity of the `{B-, C-}` strip now holds against the live join too.

**④ The two Alliance selectors are DISJOINT.**

| | test feed | prod feed |
| --- | --- | --- |
| in both selectors | 0 | 0 |
| this spec's `source_center_acronym ∈ {CIAT, BIOVERSITY}` only | **380** | 0 |
| legacy `lead_institution_object.acronym === 'ABC'` only | 0 | **32** |

They share **no** projects. This corroborates DD-9 / **OQ-7** from a second direction: the legacy admin picker is not merely dropping lower-case `bilateral` — it is selecting an entirely different population. S2 must pick one selector deliberately; they are not variants of the same idea.

## 5. What this does NOT establish — stated, not implied

- **The test feed is not production.** These numbers describe `clarisatest-back`. Production holds an older 299-row dataset with none of the upstream fields. When CLARISA promotes the contract, **re-run this reading before trusting any of it for release** — the report carries its host precisely so the two are never confused.
- **The 88.4 % ceiling framing assumes** contracts map to distinct projects. `AMBIGUOUS = 0` proves no contract matched more than one project; it does not prove two contracts never matched the same one. The conservative claim — 336 matches against a ≤380 ceiling — holds either way.
- **`UNRESOLVED` was not sampled for causes.** The 10 samples show contract codes with no match; nobody has confirmed *why* each fails. If S2 wants to push past 88 %, that residue needs its own look.

## 6. Reproducing this

The reading was taken by instantiating the real service against the DEV `DataSource` with `ARI_CLARISA_HOST` overridden per environment. The endpoint itself (`GET /api/bilateral-project-mappings/coverage-report`, admin-only) produces the same payload once the server is running — that is the intended route, and it re-measures on demand, which is the whole point of building an instrument rather than writing a number into a document.
